## Executive result

Frappe 16.22.0, ERPNext 16.22.0, and KodLyft FSM 0.0.1 install cleanly on a new MariaDB site. Three consecutive migrations completed successfully, the aggregate Bench asset build completed, Console and Portal build and return HTTP 200 from an isolated development server. The mobile web bundle builds, but the native Android debug build is blocked because the host only provides Java 11 while Android Gradle Plugin requires Java 17. The Frappe test run is blocked during the framework's pre-test record generation because `Payment Gateway` is absent. No production site or process was changed.

The architecture phase is **proposed, not approved**. No maintenance DocTypes or feature code may be started until all ADRs, the ERD, and the state matrix are approved.

## Reproducible installation

Starting from a Frappe v16 bench with ERPNext v16 and Python 3.14:

```bash
cd /path/to/frappe-bench
bench get-app fsm https://github.com/alaalsalam/fsm.git --branch develop
bench new-site fsm-dev.localhost --install-app erpnext
bench --site fsm-dev.localhost install-app fsm
bench --site fsm-dev.localhost migrate
bench --site fsm-dev.localhost migrate
```

Frontend dependency installation currently requires Node 22.12 or later despite the root manifest declaring Node 20 or later:

```bash
cd apps/fsm/frontend
nvm use 24.16.0
yarn install --frozen-lockfile
yarn build:console
yarn build:portal
yarn build:mobile
cd ../../..
bench build --app fsm
bench --site fsm-dev.localhost serve --port 8017 --noreload
```

Verify:

```bash
curl -I http://127.0.0.1:8017/fsm-console
curl -I http://127.0.0.1:8017/book
```

## Actual defects and gaps

| ID | Severity | Finding | Disposition |
|---|---:|---|---|
| BL-001 | High | Node engine contract is false: Node 20 is declared but cannot install the lockfile. | Correct manifest/CI to Node `>=22.12`; do not loosen engine checks. |
| BL-002 | High | `fsm/www` was absent, so both web SPA builds failed after successful Vite compilation. | Fixed by `67c0475`; regression test still needed. |
| BL-003 | High | Native Android debug cannot build on the current JDK 11. | Provision an isolated JDK 17+ and Android SDK, then rerun `yarn android:dev`. |
| BL-004 | High | Backend suite cannot reach FSM tests because framework test fixtures require missing `Payment Gateway`. | Resolve the Frappe/ERPNext v16 payments test dependency or install the official compatible dependency on the test site. |
| BL-005 | High | Only three Python test methods exist; eleven generated test modules are placeholders. All frontend suites contain zero tests. | Establish contract, permission, state-machine, and route smoke tests before feature work. |
| BL-006 | Medium | Token generation makes `design/src/tokens.ts` fail Prettier. | Make generator output deterministic and formatter-compliant. |
| BL-007 | Critical | Multiple write paths use `ignore_permissions=True` without a uniform explicit authorization guard. | Block next-phase implementation until ADR-008 is approved and guards are added. |
| BL-008 | Critical | Several whitelisted analytics/list endpoints use `frappe.get_all`, bypassing user permission filters. | Replace with permission-aware queries or explicit scoped authorization. |
| BL-009 | High | Mobile `JobListView.vue` contains hard-coded sample jobs as fallback/demo data. | Remove before any field trial; the approved rule is live data only. |
| BL-010 | Medium | No Frappe Reports, Dashboards, Dashboard Charts, or Workspaces are shipped; analytics exists only as custom APIs/UI. | Treat README reporting claims as partial. |
| BL-011 | Medium | Setup source requests no desk access for `FSM Customer`, but the installed role reports desk access enabled. | Reconcile fixture/install semantics and add an assertion test. |
| BL-012 | Medium | Scheduler methods call `frappe.db.commit()` directly. | Remove application-level transaction commits in a later authorized hardening phase. |
| BL-013 | Medium | Mobile offline behavior is not implemented: no durable queue, conflict policy, sync cursor, or encrypted local operational store. | Follow ADR-009 before claiming offline support. |
| BL-014 | Medium | UI is English-first and lacks an audited RTL/localization implementation. | Follow ADR-010 and add RTL visual/interaction tests. |
