## Executive result

Frappe 16.22.0, ERPNext 16.22.0, official Frappe Payments, and DIGIT FSM 0.0.1 install and migrate in the v16 development bench. FSM is installed on the designated development site `digit16.trilogy-erp.com`; Console, Portal, Mobile Web, and the Android debug package build successfully. The missing `Payment Gateway` owner was identified as official `frappe/payments`; pinning its `develop` revision restored the clean FSM test run. JDK 17 and Android Platform 36 are isolated to the Android build command while the server default remains Java 11. The production bench `/home/erpnext/frappe-bench-startd-prod` was not changed.

ADR-001 through ADR-010 are accepted by GATE-001 with their recorded constraints. This approval does not start the next phase or authorize new maintenance DocTypes.

## Reproducible installation

Starting from a Frappe v16 bench with ERPNext v16 and Python 3.14:

```bash
cd /path/to/frappe-bench
bench get-app fsm https://github.com/alaalsalam/fsm.git --branch develop
bench new-site <clean-v16-test-site> --install-app erpnext
bench --site <clean-v16-test-site> install-app fsm
bench --site <clean-v16-test-site> migrate
bench --site <clean-v16-test-site> migrate
```

Frontend dependency installation currently requires Node 22.12 or later despite the root manifest declaring Node 20 or later:

```bash
cd apps/fsm/frontend
nvm use 24.16.0
yarn install --frozen-lockfile
yarn build:console
yarn build:portal
yarn build:mobile
cd ../../..
bench build --app fsm
bench --site digit16.trilogy-erp.com serve --port 8017 --noreload
```

Verify:

```bash
curl -I http://127.0.0.1:8017/fsm-console
curl -I http://127.0.0.1:8017/book
```

## Actual defects and gaps

| ID | Severity | Finding | Disposition |
|---|---:|---|---|
| BL-001 | High | Node engine contract is false: Node 20 is declared but cannot install the lockfile. | Correct manifest/CI to Node `>=22.12`; do not loosen engine checks. |
| BL-002 | High | `fsm/www` was absent, so both web SPA builds failed after successful Vite compilation. | Fixed by `67c0475`; regression test still needed. |
| BL-003 | High | Native Android debug required isolated Java 17 and Android SDK 36. | **Closed**; server default restored to Java 11 after installation. |
| BL-004 | High | Framework fixtures required missing `Payment Gateway`. | **Closed** with its official owner `frappe/payments` at recorded SHA; CI installs it before ERPNext. |
| BL-005 | High | Security/frontend suites lacked effective coverage. | **Closed for gate scope** with 13 backend, 10 frontend unit, and 6 E2E tests. Placeholder domain tests remain future debt. |
| BL-006 | Medium | Token output was not Prettier-clean. | **Closed** by formatting deterministic generated output. |
| BL-007 | Critical | HTTP writes used bypasses without a uniform root guard. | **Closed** by `fsm.security`, authorization hooks, negative tests, and the bypass register. |
| BL-008 | Critical | User-sensitive reads could bypass row permissions. | **Closed** through `get_list` or explicit root/company/warehouse scope. |
| BL-009 | High | Mobile `JobListView.vue` contains hard-coded sample jobs as fallback/demo data. | Remove before any field trial; the approved rule is live data only. |
| BL-010 | Medium | No Frappe Reports, Dashboards, Dashboard Charts, or Workspaces are shipped; analytics exists only as custom APIs/UI. | Treat README reporting claims as partial. |
| BL-011 | Medium | Setup source requests no desk access for `FSM Customer`, but the installed role reports desk access enabled. | Reconcile fixture/install semantics and add an assertion test. |
| BL-012 | Medium | Scheduler methods called `frappe.db.commit()` directly. | **Closed**; framework-owned scheduler transactions are retained. |
| BL-013 | Medium | Mobile offline behavior is not implemented: no durable queue, conflict policy, sync cursor, or encrypted local operational store. | Follow ADR-009 before claiming offline support. |
| BL-014 | Medium | UI is English-first and lacks an audited RTL/localization implementation. | Follow ADR-010 and add RTL visual/interaction tests. |
| BL-015 | Critical | Guest registration shadowed translation `_` and lacked atomic negative coverage. | **Closed** with renamed separator, fixed payload/roles/rate limit/savepoint, and four registration tests. |
| BL-016 | Low | Two Python files were not Ruff formatted. | **Closed**. |
